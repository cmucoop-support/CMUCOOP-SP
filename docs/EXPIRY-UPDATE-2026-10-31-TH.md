# ระบบวันหมดอายุ — รุ่น 31/10/2026

ชุดนี้เป็นไฟล์แก้ไขสำหรับนำขึ้นระบบเดิม ยังไม่ได้ติดตั้งบนเว็บจริง

## สิ่งที่แก้ตามคำขอ

1. กล้องบาร์โค้ดใช้พื้นที่ภาพเต็มกรอบ แทนภาพแนวตั้งแคบกลางจอ อ่านจากบริเวณที่แสดงจริง สลับอ่านภาพกลางกรอบ/ภาพหมุน รองรับ EAN-13, EAN-8, UPC และ Code 128/39/ITF ตามเดิม ต้องอ่านค่าเดียวกันซ้ำภายในช่วงสั้นก่อนยืนยัน มีซูม และไฟฉาย/โฟกัสเมื่อกล้องรองรับ
2. ปุ่ม **ถ่ายรูปอ่านวันที่** เปิดกล้องถ่ายฉลาก อ่านวันที่บนเครื่อง แล้วเติมช่องวัน/เดือน/ปีที่ยังเลือกแก้ได้ ก่อนกดบันทึกควรตรวจให้ตรงฉลาก หากอ่านไม่พบ วันที่เดิมจะยังอยู่ หากมีหลายวันที่จะแสดงให้เลือก สามารถลากกรอบเฉพาะบรรทัดวันที่แล้วกด **อ่านอีกครั้ง** ได้
3. **บันทึกและเพิ่มถัดไป** ใช้เลขล็อตเดิม เช่น `LOT-000123-1`, `LOT-000123-2` และ `LOT-000123-3` โดยคงสาขาและจุดวาง ส่วนสินค้าและวันที่ให้ระบุใหม่ เมื่อปิดฟอร์มหรือกดบันทึกเสร็จ แล้วเลือก **เพิ่มล็อตใหม่** จะเริ่มล็อตใหม่ เลขลำดับออกจากเซิร์ฟเวอร์ จึงไม่ซ้ำเมื่อบันทึกพร้อมกัน
4. ปุ่ม **ลบรายการ** อยู่ในสินค้าแต่ละแถว และขอยืนยันชื่อรายการก่อนลบ ลบแล้วออกจากรายการทุกสถานะและยอดแจ้งเตือน รายการอื่นในล็อตยังอยู่ ระบบเก็บร่องรอยการลบและคำขอบันทึกในฐานข้อมูล เพื่อไม่ให้การส่งซ้ำสร้างรายการกลับมา เลขลำดับที่ลบแล้วไม่ถูกนำกลับมาใช้
5. วัน เดือน ปีใช้รายการเลือกเป็นตัวเลขทั้งหมด เดือนเป็น `01`–`12` ปีในช่องเลือกเป็น **ค.ศ.** ส่วนวันที่ในตารางและประวัติแสดงเป็นตัวเลขตามปี **พ.ศ.** ของภาษาไทย พร้อมตรวจวันที่ไม่มีจริง เช่น 31/02

ข้อมูลล็อตเก่าไม่ถูกเขียนทับ และแสดงเป็นเลขล็อตเดิมต่อท้าย `-1` สิทธิ์ลบใช้สิทธิ์เพิ่ม/แก้ไขระบบวันหมดอายุเดิม ผู้ดูอย่างเดียวลบไม่ได้ จำนวนบนการ์ดนับเป็นรายการสินค้าในล็อต

## วิธีติดตั้ง

1. เปิด `Cloudflare-Worker/worker-copy.txt` คัดลอกทั้งไฟล์แทน Worker เดิมใน Cloudflare Dashboard แล้ว Deploy โดยใช้ Worker และ D1 binding `DB` เดิม หรือใช้ซอร์สทั้งหมดใน `worker/` กับ Wrangler ตามวิธีเดิม
2. นำ `expiry.html`, `assets/js/pages/expiry.js`, `assets/js/shared/barcode-scanner.js`, `assets/js/shared/expiry-date-reader.js`, `assets/css/pages/expiry.css` และโฟลเดอร์ **`assets/vendor/ocr/` ทั้งโฟลเดอร์** ขึ้นเว็บเดิมตามตำแหน่งเดิม สามารถอัปโหลดทุกไฟล์ในชุด ZIP ทับชุดเดิมได้
3. ต้องอัปเดตทั้ง Worker และหน้าเว็บ แล้วเปิดหน้าใหม่/รีโหลดเพื่อรับไฟล์รุ่น `16.5` โฟลเดอร์ OCR ต้องเข้าถึงได้ผ่าน URL เดียวกับเว็บ และโฮสต์ต้องเสิร์ฟไฟล์ `.wasm` และ `.gz` ได้ตามปกติ
4. Worker จะเพิ่มตาราง `expiry_item_links` และ view `expiry_records` อัตโนมัติเมื่อมีคำขอ โดย schema version เป็น `expiry-items-1` คำขอ POST แรกหลังอัปเกรดจะถูกส่งใหม่โดยตัวเชื่อมเดิม หากจัดการ migration เอง ใช้ `worker/migrations/0005_expiry_items.sql` หลัง migration เดิม 0001–0004

ไฟล์ที่ผู้ใช้แนบมาไม่ได้ถูกรวมลงใน ZIP

## OCR และกล้อง

- รูปต้องเห็นวันที่ชัด ถ่ายใกล้ฉลากและให้แสงพอ การอ่านไม่ชัดอาจให้ผลผิด จึงต้องตรวจค่าก่อนบันทึก
- รองรับวันที่ตัวเลข เช่น `27/06/2027`, `27.06.27`, `2027-06-27`, `27062027`, ปี พ.ศ. และเดือนย่อภาษาอังกฤษ เช่น `27 JUN 27` ตัว OCR ใช้ข้อมูลภาษาอังกฤษ จึงเหมาะกับวันที่ตัวเลขและอักษรอังกฤษบนฉลาก
- ใช้ Tesseract.js 6.0.1 และ core 6.0.0 รวมไลบรารีและข้อมูลภาษาไว้ในชุดแล้ว ไม่ต้องตั้ง API key และไม่ส่งรูปไปยัง API ภายนอก การอ่านครั้งแรกอาจใช้เวลาสักครู่
- กล้องต้องเปิดผ่าน HTTPS หรือ localhost การซูมใช้กล้องถ้ารองรับ มิฉะนั้นขยายภาพบนเครื่อง ปุ่มไฟฉายแสดงเฉพาะกล้องที่รายงานว่ารองรับ
- แหล่งอ้างอิงและ SHA-256 ของไฟล์ OCR อยู่ที่ `assets/vendor/ocr/PROVENANCE.json` พร้อมไฟล์สัญญาอนุญาต อ้างอิง API: https://github.com/naptha/tesseract.js/blob/master/docs/api.md

## การตรวจสอบ

- ทดสอบ Node ทั้งชุด 89 รายการผ่าน รวมการต่อล็อตพร้อมกัน ส่งคำขอซ้ำ ลบแยกรายการ สิทธิ์ผู้ดู การชนกันระหว่างแก้ไข/ลบ การย้อนคืนธุรกรรมเมื่อบันทึกประวัติล้มเหลว และการอัปเกรดฐานข้อมูลเก่า
- ตรวจ syntax, imports, การเรียก API และไฟล์อ้างอิงผ่าน
- ทดสอบ Chrome ด้วยภาพบาร์โค้ดจริงในวิดีโอจำลอง และ OCR จริงจากไฟล์ที่รวมในชุด รวมการแก้วันที่หลังอ่าน การเลือกเมื่อมีหลายวันที่ และหน้าจอมือถือ 390 × 844
- ภาพ HEIC ที่แนบมาแปลงเพื่อทดสอบในเครื่อง อ่านได้ **27/06/2027** เมื่อครอบเฉพาะบรรทัดวันที่ ภาพเต็มอ่านไม่ชัด
- ยังไม่ได้ทดสอบการจับภาพจากกล้อง iPhone/Android จริง หรือโฮสต์จริงของผู้ใช้
