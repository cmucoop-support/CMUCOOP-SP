# CMUCOOP SUPPORT — ฉบับจัดโครงสร้างและทะเบียนสินค้า

เว็บเดิมยังเข้าผ่าน `index.html`, `barcode.html`, `stock.html`, `market.html`, `expiry.html` และหน้าอื่นตาม URL เดิมได้ เพิ่ม `catalog.html` สำหรับข้อมูลสินค้าตามสาขา

## สิ่งที่ปรับปรุง

- แยก JavaScript/CSS ออกจาก HTML แบ่งโฟลเดอร์โค้ดหน้าเว็บ ส่วนกลาง รูปภาพ ฟอนต์ และไลบรารี
- แยก Worker จากไฟล์รวมเป็นโมดูลตามระบบ พร้อมส่วนกลางสำหรับฐานข้อมูล การยืนยันตัวตน HTTP และ schema
- รวมฟังก์ชัน URL ที่ซ้ำกันไว้จุดเดียว ตัดเอกสารซ้ำและรายงานผลตรวจเก่าที่ไม่ตรงกับโค้ด
- หน้า stock รับข้อมูลบาร์สินค้าใหม่เฉพาะเมื่อ revision เปลี่ยน ลดการส่งแค็ตตาล็อกบาร์ซ้ำทุกครั้งที่โหลด
- หน้า market รวมการเขียนแบบร่างหลายครั้งในช่วง 250 มิลลิวินาที และเขียนแบบร่างล่าสุดก่อนบันทึก/เปลี่ยนหน้า/ซ่อนหน้า โดยตรวจบัญชีเจ้าของแบบร่าง
- ทะเบียนสินค้าบันทึกเฉพาะรายการที่เปลี่ยน แบ่งคำสั่งตามขนาด UTF-8 ใช้ดัชนีและการแบ่งหน้า ไม่ส่งทั้งทะเบียนไปที่เบราว์เซอร์

## การ์ดข้อมูลสินค้าตามสาขา

รวมข้อมูลสินค้าจาก 4 ระบบที่มีข้อมูลสินค้าในโครงการนี้: บาร์สินค้า สินค้าค้างสต็อก เช็คราคาตลาด และล็อตวันหมดอายุ ระบบเสียง เพลง และ TV ไม่มีรายการสินค้า จึงไม่สร้างสินค้าจากระบบเหล่านั้น

เทียบด้วยรหัสสินค้าและสาขาที่ปรับช่องว่าง/ตัวพิมพ์แล้ว เก็บรหัสต้นฉบับเป็นข้อความ จึงรักษาเลขศูนย์นำหน้าไว้ ชื่อเหมือนกันอย่างเดียวไม่ทำให้สินค้าคนละรหัสถูกรวม รหัสที่มี P นำหน้าไม่ถูกตัดทิ้งโดยเดา ข้อมูลที่ไม่มีรหัสแยกเป็นรายแหล่งข้อมูล

บาร์สินค้าไม่มีสาขาในฐานข้อมูลเดิม จึงแสดงเป็น **ข้อมูลกลาง** และใช้เติมรายละเอียดให้สินค้าของสาขาที่รหัสตรงกัน ไม่สรุปว่าบาร์สินค้าทุกรายการมีอยู่ทุกสาขา หน้าใหม่แสดงชื่อที่ขัดแย้งกัน พร้อมข้อมูลอ้างอิงจากแต่ละระบบ ค้นหา กรองสาขา/ระบบ และดูรายละเอียดแบบแบ่งหน้าได้ จำนวนจากแต่ละระบบแสดงแยกกัน ไม่บวกเป็นยอดคงเหลือรวม

เมื่อ API ของระบบต้นทางบันทึกข้อมูลสำเร็จ Worker จะอัปเดตทะเบียนก่อนตอบกลับ มีตัวบอกการเปลี่ยนแปลงที่บันทึกพร้อมข้อมูลต้นทางใน transaction เพื่อไม่ให้ลืมอัปเดตเมื่อคำขอล้มเหลวกลางทาง ถ้าอัปเดตทะเบียนไม่สำเร็จ ข้อมูลต้นทางยังถือว่าบันทึกสำเร็จและหน้าจอแจ้งว่าทะเบียนรออัปเดต การเปิดทะเบียนครั้งถัดไปจะลองซ่อมข้อมูลอนุพันธ์ให้อัตโนมัติ ไม่ต้องกดบันทึกต้นทางซ้ำ

แท็บที่เปิดทะเบียนจะรับสัญญาณขนาดเล็กเมื่อมีการบันทึกจากแท็บอื่นบนเว็บเดียวกัน ไม่มีการ polling เป็นระยะ เมื่อกลับมาเปิดแท็บจะตรวจข้อมูลใหม่อีกครั้ง

Admin เห็นการ์ดใหม่ทันที ผู้ใช้อื่นต้องได้รับสิทธิ์ **ข้อมูลสินค้าตามสาขา** ในหน้าตั้งค่า (`product_catalog`) ข้อมูลที่ API นี้ส่งไม่มีต้นทุน ราคาขาย หรือกำไร

## โครงสร้าง

```text
*.html                       หน้าเว็บและ URL เดิม + catalog.html
assets/
  js/shared/                 API shim, navigation, scanner, accessibility
  js/pages/                  โค้ดแยกตามหน้า
  css/shared/                สไตล์และฟอนต์ส่วนกลาง
  css/pages/                 สไตล์แยกตามหน้า
  images/ fonts/ vendor/     รูปภาพ ฟอนต์ ไลบรารีและใบอนุญาตเดิม
worker/
  index.js                   entry point เดิมสำหรับ deploy
  src/core/                  HTTP, database, schema, registry, log, config
  src/modules/               auth, portal, barcode, stock, market, expiry ฯลฯ
  src/catalog-sync.js        เชื่อมการบันทึกแต่ละระบบเข้าทะเบียน
  src/guards.js              ป้องกันการเขียนทับจากคำขอพร้อมกัน
  migrations/                SQL เพิ่มโครงสร้างตามลำดับ
  scripts/ tests/            ตรวจ syntax, assets, API และทดสอบพฤติกรรม
docs/                        คู่มือและรายละเอียดการจัดเก็บ
```

## ติดตั้งหรืออัปเดตระบบจริง

1. เก็บสำรอง D1 ตามกระบวนการของร้านก่อนอัปเดต และใช้ staging ตรวจข้อมูลของร้านจริงก่อน
2. ตรวจ `worker/wrangler.toml` ให้ชี้ฐานข้อมูลเดิมที่ต้องการ ห้ามสร้างฐานข้อมูลใหม่มาทับข้อมูลเดิม
3. ในโฟลเดอร์ `worker` รัน `npx wrangler d1 migrations apply cmucoop --remote` เพื่อใช้ migration ตามลำดับ 0001–0004 ระบบเดิมที่ใช้ 0001–0003 แล้วจะเพิ่ม `0004_product_catalog.sql` โดยไม่ล้างข้อมูลเดิม
4. รัน `npx wrangler deploy` จากโฟลเดอร์ `worker`
5. อัปโหลด HTML ทุกหน้าและโฟลเดอร์ `assets/` ทั้งชุดไปโฮสติ้งเดิมพร้อมกัน URL ของ API ตั้งไว้ที่ `assets/js/shared/gas-shim.js` หากใช้ Worker เดิมไม่ต้องเปลี่ยนค่า
6. เปิด `index.html` ด้วยบัญชี Admin แล้วเปิดการ์ด **ข้อมูลสินค้าตามสาขา** การเปิดครั้งแรกจะสร้างทะเบียนจากข้อมูลเดิมทั้งหมด ผู้ใช้ทั่วไปต้องเปิดสิทธิ์ในหน้าตั้งค่า

Worker มี schema fallback สำหรับฐานข้อมูลเดิม แต่ควรใช้ migration ก่อนรับทราฟฟิกจริง อย่าลบ migration เก่าหรือเปลี่ยน binding ของฐานข้อมูลโดยไม่ตรวจสอบ ไฟล์ชุดนี้เป็นซอร์สโค้ดสำหรับติดตั้ง ยังไม่ได้ deploy ไปเปลี่ยนระบบออนไลน์ของร้าน

โค้ดส่วนหน้ารองรับโฮสติ้งแบบ static โดยไม่ต้อง build ส่วนหลังใช้ Cloudflare Worker และ D1 ตามเดิม ไม่ต้องเพิ่มฐานข้อมูลหรือบริการคิว

## ตรวจสอบในเครื่อง

ต้องใช้ Node.js 24 ขึ้นไป คำสั่งพื้นฐานไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```sh
node worker/scripts/check.mjs
node worker/scripts/audit.mjs
node --test worker/tests/*.test.mjs
```

หรือใช้ `npm run verify` จากโฟลเดอร์หลัก การทดสอบเบราว์เซอร์ใช้ `npm install`, `npx playwright install chromium`, แล้ว `npm run test:browser` ทดสอบกับฐานข้อมูล SQLite ในหน่วยความจำและเว็บจำลอง ไม่ติดต่อฐานข้อมูลร้านจริง

การทดสอบจำลองตรวจ transaction, revision, rollback, คำขอพร้อมกัน, สิทธิ์ และขนาดพารามิเตอร์ แต่ไม่แทนการทดสอบ network/CPU/หน่วยความจำ/โควตาของ Cloudflare จริง โดยเฉพาะการนำเข้าขนาดใหญ่และการสร้างทะเบียนครั้งแรก ดูข้อจำกัดใน [เอกสาร D1](https://developers.cloudflare.com/d1/platform/limits/) และรายละเอียด transaction ใน [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)
